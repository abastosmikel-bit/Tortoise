# Tortoise wrap-up studies: decisions and protocols

Folder `results/wrapup/`.
Each study's protocol is written and committed here **before its first evaluation run**. Changes after that are dated
deviations (section "Deviations" of the study), and the affected results are re-run.

## E0. Rules for every study (2026-10-30)
1. **Tortoise v1.0 stays frozen.** Tortoise v1.0 = Variant 3 at `fitc10`, weights `rev10/eval/F_hw_m4_firstpass.npy`, host
   protocol v2.1 (`docs/SPEC.md`). Every circuit change is a **named variant** (identifier `R10.2-<name>`, prose name `candidate-<name>`; [docs/NAMING.md](../../docs/NAMING.md)) with its own builder
   (a netlist transform in `scripts/`), TFT count and stress audit, reported as a **candidate**. Adopting one is the
   author's decision; nothing here changes `docs/SPEC.md`.
2. **Tooling** (`scripts/wu.py`): imports `results/host_v21/scripts/hv21.py` (and through it host_v2, energy_host, the
   fitc10 campaign and `rev10`) read-only. Calibrations, runs and corner `.lib` files are written only under
   `results/wrapup/`. Corner files that exist in an earlier campaign are copied byte for byte. A circuit variant is a
   transform of the final netlist text applied just before ngspice runs (a wrapper around `hv2.simulate`), so it acts
   on a1, idle and classification netlists alike; with no variant the netlist is the Tortoise v1.0 netlist.
   **Tooling check (2026-10-30, before any run of these studies, not a result):** with this wrapper, the netlists of
   `host_v21/raw/E1/E1_v0550_m100_v21_s01` and `host_v2/raw/C3/C3_v0650_m070_learned_s01` are rebuilt byte-identical
   to the stored ones (absolute corner `.lib` path reduced to its file name). The smoke test (`tools/smoke_test.sh`) gave
   5/5 MATCH on the study machine (224 s).
3. **Test set (90 samples): never used for training, selection or calibration.** All training, selection and
   calibration use the 210 training samples. Each new weight set is evaluated on the test set **once**, after it is
   frozen and committed; the result is reported whatever it is. Robustness points use the fixed 20-sample test subset
   (`fitc10 summary/phase3_subset.json`), as every earlier campaign did; they are evaluation, not selection.
4. **Statistics:** accuracy = correct of N (invalid = wrong); Wilson 95 % intervals; paired comparisons per sample
   (or per die × sample) with the exact two-sided McNemar test on correct/incorrect. A "pass/fail" below is a
   pre-declared reading, not a statement about hardware.
5. **Honesty:** no "verified", "validated" or "proven"; every number reproducible from committed scripts; failures
   reported as failures; each report section has a "what this does not show" part.
6. **Git:** per-run JSONs in plain git; waveforms `*.csv.gz`, netlists `*.cir.gz` and `*_draws.json` in Git LFS.
   *(Public release: these files are not included; they can be regenerated by re-running the campaign, see [REPRODUCE.md](../../REPRODUCE.md) §6.)*
7. **Run order (CPU):** simulations run in the background on 4 processes; Study 4 (literature, no simulation) is done
   while they run.

## S1. Study 1: mode W robustness (simulation only, no circuit change) — protocol, 2026-10-30, before any S1 run

**Question.** Host protocol v2.1 runs dies whose estimate V̂ < 0.600 V in mode W (VDD on). Mode W was tested only at
µ ×1, without mismatch (host_v21 E1). Does it keep working under mobility loss, threshold drift (with the host's own
re-calibration and the mode switch that drift can cause) and size-scaled V_th mismatch?

**Circuit and protocol:** Tortoise v1.0 and v2.1 exactly (`hv21.calibrate`, `hv21.run_cls`, `hv21.run_idle`); constants
c_a1, I_ref, c_race, c_race,W, V_gate = 0.600 V unchanged. Runner `scripts/s1_modew.py`.

### S1.1 Aging proxy grid (base |V_th| 0.55 V, mode W at the start)
- Cells: |V_th| = 0.55 + ΔV_th, **ΔV_th ∈ {0, +0.10, +0.20} V** → 0.55 / 0.65 / 0.75 V, × **µ ∈ {×1, ×0.7, ×0.5}**: 9 cells.
  Global corners (`eh_v<vth>_m<mu>.lib`, fitc10 otherwise), no mismatch, as host_v2 C3.
- **Each cell is its own v2.1 calibration session** (the host re-calibrates after drift, using only its own estimates:
  a1 V̂ and µ̂ → levels, k, and **the mode, decided afresh by P2.0**). The mode each cell ends in is reported with V̂,
  its error, µ̂, k and the cross-check flag. A die that started in mode W at 0.55 V and drifted is therefore expected to
  switch to mode G once V̂ ≥ 0.600 V; whatever the calibration decides is the result.
- 20 samples per cell (the fixed subset), independent runs from the calibration start state (as E1 and C3). For
  mode-W runs, the 1 s VDD-on idle after each run is also simulated (standby, P2.4).

### S1.2 Mismatch at base 0.55 V
- The 3B-V model and **the same 5 dies** as fitc10 3B-V and host_v2 C4: size-scaled V_th only, anchor **20 mV**,
  `mc = dict(seed = 20000 + d, s_vth = 0.020, s_mu = 0.10, s_rc = 0.20, scale = "pelgrom_vth")`, d = 1…5 (the µ and R_C
  draws are taken but not applied, so each instance has the same V_th offset as in C4), on the **0.55 V global
  corner**, µ ×1. Each die is its own v2.1 calibration session (its mode is whatever its V̂ decides); 20 samples per
  die → N = 100. Idle after each mode-W run as S1.1.

### S1.3 Cells identical to existing runs (no duplicate simulation)
v2.1 is deterministic, and mode G is v2 exactly (P2.0). A cell whose v2.1 calibration record is **identical** to an
existing calibration of the same corner (same mode, levels, k, race times, and start-state node voltages within
1e-9 V) produces classification netlists identical to the existing ones. For such a cell:
1. the 20 classification netlists are built and compared byte for byte with the stored ones (`.cir.gz`, not included in this release; the
   absolute `.lib` path reduced to its file name) → `summary/s1_identity.json`;
2. 2 samples (subset #0 and #10: test samples `SUB[0]`, `SUB[10]`) are **re-simulated** under this study's tooling and
   must give the stored outcome and times (within 0.05 µs);
3. if both hold, the stored per-run outcomes are reported for the cell, labelled "reused (netlist-identical)".
   If either fails, all 20 samples are simulated and the difference is reported.
Reference calibrations: **0.55 V × µ1 → host_v21 E1** (`raw/cal/v0550_m100`, mode W); **0.65 / 0.75 V × µ1 / ×0.7 / ×0.5
→ host_v2 C3** (`raw/cal/v0650_m100` …, v2 = mode G). The 0.55 V × ×0.7 / ×0.5 cells and every mismatched die have no
earlier counterpart and are simulated in full. A cell whose calibration chooses mode W at 0.65 or 0.75 V would have
no counterpart either and would be simulated in full.

### S1.4 Comparison ("next to the corresponding v2, mode G, results")
- Aging: each S1.1 cell next to the host_v2 C3 cell with the same ΔV_th from the v2 base 0.65 V (0.65 / 0.75 / 0.85 V)
  and the same µ (C3 `raw/C3/C3_v<vth>_m<mu>_learned_*`), and next to the 0.55 V µ ×1 E1 point.
- Mismatch: the S1.2 dies next to host_v2 C4 (same 5 dies at 0.65 V, v2 = mode G: 64/100) and fitc10 3B-V at 20 mV
  (v1: 64/100). **Paired per (die, sample)** with C4: exact McNemar (indicative; the pairs share dies).

### S1.5 Pass criteria (pre-declared reading)
- A cell **works** if correct ≥ 13/20 (the band the v2 C3 grid spanned, 13–15/20, against 15/20 on the nominal die),
  **degraded** if 1–12/20, **fails** if 0/20 or its calibration fails. Validity and failure labels are reported.
- The mismatch point **matches v2** unless it is lower than C4 with paired exact McNemar p < 0.05 (then: **worse**).
- **Study 1 succeeds** if every S1.1 cell works and the S1.2 point matches v2; otherwise it reports which cells or
  which mismatch result fail, as failures.

### S1.6 Secondary item S1-F (run only after the primary runs of Studies 1–3; reported as "not run" otherwise)
Mode W **forced** at 0.65 V × µ ×1 / ×0.7 / ×0.5 (own calibration sessions with the mode forced; labelled "forced",
not the v2.1 policy): what a die that drifts from 0.55 V would do if the host kept mode W instead of switching.
20 samples per cell plus idles. Same reading as S1.5, reported separately.

### S1.7 Order
Calibrations (14 sessions, 4 processes) → classification runs of S1.1/S1.2 (4 processes) → identity check → summary
(`scripts/s1_summary.py` → `summary/s1_modew.json`, `summary/s1_tables.md`).

## S4. Study 4: prior art and the microcontroller question (no simulation) — protocol, 2026-10-30, before any lookup
1. **Lookups.** `prior_art/lookup.py` queries Crossref (`/works/<DOI>`, `query.bibliographic`), Semantic Scholar
   (`/paper/DOI:<DOI>` with abstract; search) and the arXiv API, and any datasheet or product page by URL. Every
   response is saved verbatim in `prior_art/lookups/` (not redistributed in the public release) and logged in `prior_art/lookups/LOG.jsonl` (UTC time, URL,
   HTTP status, file, SHA-256).
2. **Citation rule.** A work is cited only if a logged Crossref, arXiv or Semantic Scholar response confirms it, and it
   is cited with its DOI or arXiv ID. Candidate works recalled from memory are only search leads. Statements about a
   work's content are limited to what its abstract (from a logged API response) or a fetched page supports; at most
   one short quoted phrase per source. Anything that could not be confirmed is listed as unconfirmed, not cited.
3. **Scope** (five groups): printed/flexible ML classifiers (e.g. the Tahoori/Zervakis printed-ML and printed
   neuromorphic work); organic/OTFT neural circuits on foil; time-domain, race-logic and temporal-coding classifiers;
   unipolar (p-only) organic analog and mixed-signal circuits; wearable or wound-sensing systems with on-patch
   processing. For each: what it does, technology, size, accuracy and energy where the abstract or fetched page
   reports them, and how Tortoise differs.
4. **Novelty statement.** "New" only for a feature no confirmed source in the log shows; "not new" where one does;
   "unclear" where the search cannot exclude it (the search is not a systematic review and says so).
5. **MCU comparison.** Energy and size of an ultra-low-power MCU reading 6 analog sensor values and computing a
   6 × 5 linear classifier, including wake-up and ADC conversions, from figures in fetched (logged) datasheets or
   papers; the arithmetic is in a committed script (`scripts/s4_mcu.py` → `summary/s4_mcu.json`) with every assumption
   stated. Compared with Tortoise's 588 nJ per classification (H2-02), zero standby on the die, and its need for a
   host. Where Tortoise loses is stated plainly; conditions under which a foil classifier could still make sense are
   marked as **arguments, not results**.

## S2. Study 2: circuit fix for the 0.49 V edge (variants) — protocol, 2026-10-30 ≈ 16:30 UTC, before any S2 evaluation run

### S2.0 What was done before this protocol (disclosed; development, not results)
1. **Mechanism from stored node voltages** (`scripts/s2_mechanism.py` → `summary/s2_mechanism.{json,md}`; host_v21 E1
   waveforms at 0.49 / 0.51 / 0.53 / 0.55 / 0.61 V and host_v2 C3 at 0.65 V, all 20 subset samples each, no
   simulation). At 0.49 V, on all 20 samples, the idle level of `win` 100 µs into C2 is 2.445 V (0.51 V: 2.068 V; 0.65 V:
   1.113 V), so the inverter output `lockb` is 2.228 V instead of 2.888 V, and the lock devices X89… (gate `lockb`,
   source VDD) see V_SG ≈ 1.07 V > |V_th|: **the lock-out is partly engaged before any class has won** and holds every
   `d` high. The leading class's `d` then falls only to 2.834 V (trip-driver V_SG ≤ 0.476 V < |V_th|) and its `na` peaks
   at 1.51–1.66 V: no regeneration (16 timeouts, 4 `none_latched`). The idle `win` level is set by the five P_k
   pull-ups (gate `nb` ≈ 2.87 V, V_SG ≈ 0.43 V, subthreshold leakage that grows as |V_th| falls) against the weak idle
   pull-down X80 (5/120 µm; its length was multiplied by 6 in Variant 3, fitc10 D4). This refines the v2.1 report's
   "comparator/latch swing too weak": the swing is weak because the lock is half on.
2. **Development screen** (`scripts/s2_dev.py` → `summary/s2_dev.json`, `raw/S2dev/`): one **training** sample (#123,
   class 5), |V_th| 0.45 / 0.49 V (mode W) and 0.65 V (mode G), true-|V_th| levels, k = 1, start states borrowed from
   Tortoise v1.0 calibrations; no test sample used. Tortoise v1.0: `none_latched` at 0.45 and 0.49 V, class 5 at 0.65 V.
   X80 L 60 µm, X80 L 20 µm, P_k L 10 µm: class 5 at 0.49 V, `none_latched` at 0.45 V (the lock stays off — `lockb`
   2.9 V — but `na` regenerates too slowly for the 50 µs early-end window), nominal race within 0.02 µs of Tortoise v1.0.
   XI2 L 60 µm: `none_latched` at 0.49 V. X80 L 20 + trip drivers W 400 µm: all five latches stuck high at 0.45 V and
   the nominal race 13 µs shorter.

### S2.1 Variants (sizing only, no device added; 134 TFTs each)
- **candidate-edgeA**: X80 (idle pull-down of `win`) **L 120 → 20 µm**, W 5 µm unchanged — the base-design length before
  Variant 3's ×6 lengthening; the strongest single-device fix of the screen.
- **candidate-edgeB**: the five P_k pull-ups X90, X100, X110, X120, X130 **L 5 → 10 µm**, W 80 µm unchanged — halves the
  leakage that lifts `win`; a different device, same mechanism.
- Not taken (from the screen): X80 L 60 µm (same mechanism as edgeA, weaker), XI2 L 60 µm (failed at 0.49 V), X80 L 20 +
  X83 W 400 µm (stuck latches at 0.45 V, nominal race changed). Only two variants are run (the campaign specification allows up to three)
  to keep the simulation budget; this is a scope choice made before any evaluation run.
- Builder: `scripts/s2_variants.py` (netlist transform of the final Tortoise v1.0 netlist, applied to a1, idle and
  classification netlists alike).

### S2.2 Runs per variant
1. **Design constants:** a design-time run of the variant on the nominal die (`hv21.calibrate(nominal=True)`); if its
   a1 offset is within 0.1 mV and its I_ref within 0.1 % of Tortoise v1.0's, Tortoise v1.0's constants are kept (the variants
   do not touch the a1 current path, so this is expected); otherwise the variant's own constants are used and reported.
2. **v2.1 calibration session** at each |V_th| ∈ {0.65, 0.49, 0.51, 0.47, 0.45} V (µ ×1, no mismatch; the mode is
   whatever each calibration decides), then the 20 subset samples, independent runs from the calibration start state,
   with the 1 s idle after each mode-W run (standby). **Order: 0.65 V first (nominal check), then 0.49, 0.51, 0.47,
   0.45 V.**
3. **Nominal check (pass/fail):** at 0.65 V the 20 per-sample outcomes (latched set at the read, validity, failure
   label) must be identical to Tortoise v1.0's (host_v2 `raw/C3/C3_v0650_m100_learned_*`; v2.1 mode G = v2). If not, the
   variant **fails** and its other points are not run.
4. A point **works** if correct ≥ 13/20 (as S1.5). The variant's **lower edge** = the lowest tested |V_th| from which
   every higher tested point works. Tortoise v1.0 references: 0.49 V 0/20, 0.51 V 15/20 (host_v21 E1); 0.45 / 0.47 V under
   v2.1 were never run and are **not run here** (v2 gave 0/20 at both, host_v2 C6); they are reported as "not run".
### S2.3 Best variant and its evaluation
- **Best variant** = lowest lower edge; tie → more correct summed over 0.45–0.51 V; tie → edgeA (one device changed).
- For the best variant only: **all 90 test samples at the nominal die** (v2.1, mode G, its own calibration session),
  paired per sample with Tortoise v1.0's 90 (host_v2 C1, H2-01): identical outcomes expected; any difference is reported
  with exact McNemar. Plus the **stress audit**: the host_v2 C2 procedure (every TFT including the crossbar, max |V_GS|
  and |V_GD| vs 3.5 V; 5 runs: maxsum #17, minsum #61, maxcol #29, mincol #1, and #31 after #30 with a power-down +
  1 s off), power-up and power-down ramps at 1× (10 µs); the variant's nominal calibration.
- **Study 2 succeeds** if the best variant passes the nominal check, works at 0.49 V, keeps 90/90 nominal outcomes and
  has 0 TFTs above 3.5 V; otherwise the failing item is reported as a failure. A variant is a **candidate**
  (`R10.2-edge…`), not part of Tortoise v1.0.

## S3. Study 3: bias-row variant candidate-bias (`R10.2-bias`) — protocol, 2026-10-30 ≈ 16:30 UTC, before any S3 SPICE run and any CV
**Done before this protocol (tooling, training data only):** `scripts/s3_train.py check` — with an empty bias row and
The weight-retraining study's parameters the extended surrogate reproduces `weights_schemeA/scripts/surrogate.py` margins on T to
< 1e-12 µs (old weights and cand_a; nominal and 10 dies), `summary/s3_check.json`. `scripts/s3_train.py probe` — the
S3.2 probe matrix (below). A netlist check of the variant (138 TFT instances for the probe). No SPICE run, no CV.

### S3.1 Design
- A 7th crossbar row `row7`, driven by the host, with one bank per class: `potftseg`, W = 10 µm × F_b[k], L = 54 µm,
  drain `ap_k`, gate `row7`, source VDD (empty banks removed). Same device and geometry rule as the input banks.
- **Level V₁** (the C1 level, 3.3 − V̂ − 0.83 V): the bias then follows the host's |V_th| re-trim exactly like the
  inputs. **Pulse: from t₀ (start of C1) for WMIN + x_b·T₁·k with x_b = 0.5** (105 µs at k = 1, inside the C1 window
  of 20 + 170·k µs; 0.2 µs edges). Reasons: a bias row is a 7th input with constant value, so the scheme-A timing
  (t₀, WMIN, T₁, k-scaling for mobility) is reused unchanged; x_b = 0.5 gives one bias finger ≈ α·105 µs ≈ 10 mV of rail
  (≈ 17 µs of race at the nominal C2 slope, ≈ 2 G_res), fine enough for the biases a float classifier wants (0–7
  input-fingers-at-x=1 on the training data, i.e. ≤ ≈ 13 bias fingers) while keeping the banks ≤ 300 µm wide.
- **Off (3.3 V)** in the calibration/sampling window, in C2 (so every column's C2 slope and the `ref` sampling are those
  of the 6 input rows), during the whole calibration session (a1 and both cross-check races, so the a1 estimator and
  the race cross-check are unchanged), and like every row at power-up/down and idle.
- Host interface: 11 driven lines instead of 10 (one more pad). TFTs = 113 + input banks + bias banks.
  Two bank budgets: **b134** (input + bias banks ≤ 21 → ≤ 134 TFTs) and **b138** (input ≤ 21, bias ≤ 4 → ≤ 138; a
  common bias is irrelevant to the race, so at most 4 bias banks are needed).
### S3.2 Surrogate extension and recalibration (≈ 40 SPICE runs, training samples only)
- Extension: rail at C2 start gains α_b·F_b[k]·(WMIN + x_b·T₁); the C2 slope is unchanged (bias row off).
- **Why a recalibration is needed:** the weight-retraining study calibrated the surrogate under the v1 protocol (warm start); under v2.1
  mode G the 1 s-off power-up leaves the rails below the reset floor (rail reset level 0.334 V on every class vs
  0.898 V under v1; host_v2 C3 and fitc10 Phase 1 runs), so R_k is common and the reset-switch mismatch term does not
  apply (it is switched off in the surrogate's mismatch dies).
- **Probe matrix** (`weights/S3_probe.npz`, fixed now): config (le60, m = 30 µs, b138) trained on all of T with the
  weight-retraining study's v1 parameters and α_b = α → F_b = [4, 3, 11, 10, 0], column sums 60, 21 input + 4 bias banks, 138 TFTs.
- **Runs:** the 40 K training samples (weight-retraining study `splits.json` "K") with the probe matrix, v2.1 at the nominal die
  (design-time run + calibration session of the variant; constants rule as S2.2.1). Fit (`scripts/s3_runs.py recal`):
  common R, α, α_b (least squares on the 200 rails at C2 start), γ (per-class C2 slopes from the waveforms), Θ_k
  (median of V_k + γ n_k t_trip over the runs class k won), gap factor (median SPICE gap estimate / surrogate gap);
  **G_res kept at 8.70 µs** (weight-retraining study). Reported: rms residual, α_b/α, in-sample winner/validity/outcome agreement.
- **Acceptance:** winner agreement ≥ 36/40. If not met, the surrogate is not used for selection, the study stops before
  any test-set run and this is reported as a failure of the training step.
### S3.3 Training, CV and selection (training set only)
- Family (a) of the weight-retraining study extended: maximise the number of training samples whose class wins by ≥ G_res + m on the
  nominal recalibrated surrogate (+10⁻³ × mean sigmoid tie-break); greedy integer descent over input-finger moves
  (shift 1–3 fingers between rows of a column; in le60 also ±1–3 in one bank) and bias moves (F_b[k] ± 1–3,
  0 ≤ F_b ≤ 30); starts: rounded constrained LR with bias, λ ∈ {1e-4, 1e-3, 1e-2} (no old-weights start).
- Configs: column-sum mode {eq60, le60} × m ∈ {10, 20, 30, 45} µs × budget {b134, b138} = 16, each on the 20 group
  splits of T (weight-retraining study `cv_T`). Score on the validation folds: **S3 = 0.5·A_nom + 0.5·A_mm** (A_mm: 500 analytic dies,
  size-scaled V_th, anchors 20/35 mV, seed 41000; bias banks z from seed + 500000; reset term off).
- **Finalists (2):** the best b134 config and the best b138 config by mean S3, each retrained on all of T
  (`weights/S3_<config>.npz`). Each gets its design-time run and calibration session and **40 SPICE runs on S**
  (the weight-retraining study's 40 held-out training samples). **Winner = higher SPICE correct on S**; tie → higher CV S3.
- The winner is **frozen and committed** (`weights/FROZEN_S3.json` with SHA-256; `s3_runs.py test` refuses otherwise)
  before any test-set run.
### S3.4 Evaluation of the single frozen choice
- **Test set, once:** all 90 test samples, v2.1 at the nominal die (mode G, its own calibration session). Accuracy,
  validity, failure labels, **paired exact McNemar against Tortoise v1.0's 90 outcomes** (host_v2 C1, H2-01: 62/90).
- **Mismatch:** 3B-V, anchor 20 mV, **the 5 C4 dies paired by instance** (z-scores replayed from seeds 20001–20005 over
  the Tortoise v1.0 instance list; new instances from a separate seeded stream; `scripts/s3_variant.py`), each die its own
  calibration session, the 20 subset samples → N = 100, paired per (die, sample) with host_v2 C4 (64/100).
- **Stress audit:** the C2 procedure (S2.3) with the frozen weights: maxsum #17 and minsum #61 (input sums, as C2),
  maxcol / mincol re-picked with the new column scores (x·F6 + bias drive), and #31 after #30; power-up/down at 1×;
  every TFT including the bias banks; limit 3.5 V.
- **Reported:** accuracy gain (with CI and McNemar) against the extra TFTs; yield cost with an independent-defect model
  Y = 0.98^N (N = TFT count), against 0.98^134; energy per classification (row7 driver included).
- **Reading:** "improves" only if the test accuracy is higher with paired p < 0.05; "no resolvable change" if p ≥ 0.05;
  "worse" if lower with p < 0.05. Stress must be 0 TFTs above 3.5 V. The variant is a **candidate**.

## Deviations (dated; each before the runs it affects)
- **S2-D1 (2026-10-30 17:45 UTC, before any S2 90-sample run).** The best variant's 90 nominal test runs (S2.3) reuse
  its 20 nominal-check runs at 0.65 V (S2.2.3): they are the same calibration session, the same protocol and the same
  netlists, so only the other 70 test samples are simulated. Reason: simulation budget (4 cores saturated; ≈ 150–180 s
  of CPU per run). No result has been seen that this choice could depend on.
- **Budget deviations (2026-10-30 ≈ 17:58 UTC), each before any run it affects.** Measured throughput with the four
  cores saturated is ≈ 1 classification run per minute (≈ 150–350 s of CPU per run), so the remaining declared runs
  (≈ 690) would take more than 10 h. Cuts, chosen so that every run the campaign specification names explicitly is kept:
  - **S2-D2.** Every variant runs 0.65 (done), 0.49 and 0.51 V. **0.47 and 0.45 V are run only for the better variant**,
    chosen by: more correct at 0.49 + 0.51 V; tie → candidate-edgeA (one device changed). The other variant's 0.47/0.45 V
    points are reported as "not run". The S2.3 "best variant" rule then applies to the variant that has all points.
  - **S3-D1.** Each finalist is run on **20** held-out S samples (the two S groups listed first in the weight-retraining study's
    `splits.json` "S_groups": groups 3 and 4, 4 samples per class) instead of all 40. The decision rule (more SPICE
    correct, tie → higher CV S3) is unchanged.
  - **S3-D2.** Mismatch evaluation of the frozen choice on **the first 3 of the 5 C4 dies** (seeds 20001–20003) × the
    20-sample subset (N = 60), paired per (die, sample) with host_v2 C4's runs on the same dies.
  None of the affected runs had started; no result was seen that these choices could depend on (the S2 nominal checks,
  both "identical", are unaffected).
- **S1-D1 (2026-10-31 02:20 UTC).** The 1 s VDD-on idle after each mode-W run (standby, S1.2 "idle after each mode-W
  run as S1.1") is **not simulated for the remaining mismatch runs** (die 4 samples not yet idled, all of die 5). On die 4
