# Energy / host study: decisions

Each decision is recorded **before** the runs it governs, unless marked otherwise. Circuit throughout: Variant 3 at `fitc10`
(fitc10_campaign D9/D11), weights `rev10/eval/F_hw_m4_firstpass.npy`, the Variant 3 warm start
(`results/fitc10_campaign/raw/v3/warmstart/fitc10_warm`), `RELAX=1` solver set, `.tran 100n … 0 100n`. Results apply to these
weights only (the weight-retraining study was retraining them in parallel).

  (`.gitattributes` inside this folder).

## E1. Energy accounting (B1)
- **Sources (11):** `VDD`, `VR1–VR6` (row drivers; V₁ and V₂ are levels of these PWLs, there is no separate level
  source), `V_RSTR`, `V_RSTB`, `V_PHIB`, `V_PHI`.
- **Per source, three numbers** (i_out = current out of the source into the die):
  - `net` = ∫ v·i_out dt: net energy delivered into the die (the campaign specification's definition). Can be < 0 for a line that gets
    charge back (gate discharge).
  - `pos` = ∫ max(v·i_out, 0) dt: energy pushed in, nothing credited for returned energy.
  - `host33` = 3.3 V · ∫ max(i_out, 0) dt: what a line driver powered from a 3.3 V host rail draws (charge returned by the
    die is dumped to ground). For VDD, `host33` = `pos`.
  - **Headline = sum of `net` over all 11 sources.** `host33` is reported next to it as the driver-side cost.
- **Integration:** trapezoid over the native ngspice time points (binary raw, no resampling).
- **Instrumentation:** `vdd`, every host line and the comparator-sense side of `vls` are split per block through 0 V
  sources (`VAM_<net>_<block>`). Check: the 90 instrumented runs must give the same outcome as the Phase 1 runs
  (#81 checked first: identical trip 1276.03 µs and lock latency 19.972 µs; current closure 2e-8).
- **Blocks** (device groups): `xbar` X1–X30; `dummy` X31–X60 (calibration columns); `servo` X61–X64; `lshift` X65–X66;
  `sampler` X67–X74; `rreset` X75–X79; `comp` X81–83 family; `latch` X84–88 family + XNP1–5; `lock` X89–90 family,
  X80, XI1, XI2, XWR; `spare` X141–145. The campaign specification's five blocks: crossbar = xbar; rails and reset = rreset;
  comparators = comp; latch and lock = latch + lock; reference = dummy + sampler + servo + lshift (spares separate).
  - X65 (level-shift bias) supplies `vls`, which feeds both X66 and the five comparator senses X81-family. Energy is
    attributed where it leaves VDD (X65 → reference); the sense share (`vls:comp`, internal) is reported separately.
- **Phases:** reset 0–301 µs; calibration 301–312.5 µs; C1 312.5 µs–t_C2 (507.5 µs); C2 race t_C2 → lock (`win`
  crosses 2.05 V); post-lock lock → end of window. If nothing locks, C2 runs to the end of the window.
- **One classification** = the baseline protocol from t = 0 (warm state = end state of a previous classification) to
  t_C2 + 2500 µs (the campaign window). Starting and ending in the same kind of state, so ∫P over it is the per-period
  energy of back-to-back operation.

## E2. Standby (B1.4)
- **Idle levels:** rows 3.3 V (inactive), `rstr` 3.3 V, `rstb` 3.3 V, `phib` 3.3 V, `phi` 0 V; VDD 3.3 V. These are the
  levels every line has at the end of a classification, except the rows, which return from V₂ to 3.3 V.
- **Start state:** the end of a full classification (the protocol continued; rows go 2.4 → 3.3 V at the end of the window).
- **Length:** run until the total power changes by < 1 % between the last two decades of time, or 1000 s.
- **Amendment (2026-10-25, before any standby result was used):** the first standby test (from #3's end state) was not
  steady at 1000 s (199 → 100 µW; `ref` leaks up, the rails leak down). Standby is run in two stages: stage A, 0–2 ms
  at the 100 ns step (rows return to 3.3 V); stage B from stage A's end state, rows at DC 3.3 V, free timestep, to 10⁴ s.
  The 10⁴ s and 10⁵ s runs of #3 give the same final power (98.2 µW), so 10⁴ s is used. Reported: power just after a
  classification, the power-vs-time trace, and the steady value.

## E3. Host-only energy options (B1.5), declared 2026-10-25 before running any of them
The baseline energy (first 30 runs) is ≈ 0.7 µJ, ≈ 99 % from VDD and dominated by static bias and ratioed-logic current
that flows for the whole window. Two host levers act on that time:
- **O1, adaptive race end.** The host watches the five outputs `na1–5`. 50 µs after the first output exceeds 1.65 V
  (after 320 µs), it returns every row to 3.3 V (0.2 µs edge). It reads the outputs 10 µs later, and that ends the
  classification. The next one starts there, so O1 needs its own warm start: #81 chained with O1 from the Variant 3 warm
  start until the rail reset levels change < 5 mV (the D7 rule), then all 90 samples from that state.
  - In SPICE the host is an ideal detector + timer + series row source (B-sources; not part of the die). The row current
    still flows through `VR<i>`, so the accounting is unchanged.
  - Energy is integrated to the read time. Validity is scored as for the baseline: the latched set at the end of the
    simulated window (rows held at 3.3 V after the stop), which shows the read state also holds. The latched set at the
    read time is reported too.
  - Δ = 50 µs = lock latency (≈ 20 µs) + latch regeneration (≈ 25 µs) + margin.
- **O2, VDD power-gated idle.** Between classifications VDD and every line are at 0 V (standby ≈ 0, not simulated:
  no source is on). Each classification is a cold start: VDD, the rows and `phi` ramp 0 → protocol level over 0–10 µs,
  `rstr` is low from t = 0, and the rest follows the protocol. Baseline 2500 µs window. No warm start (there is no
  history). Note: cold rails start below the p-type reset floor (≈ 0.1 V instead of ≈ 0.9 V at the end of reset).
- **O12 = O1 + O2:** cold start, adaptive end, VDD off after the read.
- Each option: 90 samples, instrumented. Reported next to the baseline: energy (median, range), accuracy, validity, and
  per-sample outcome changes. A per-classification figure that includes idle time between classifications is given as a
  function of the repetition period, from the standby trace.

## E4. Re-trim tolerance (B2), declared 2026-10-25 before running
- **Points:** |V_th| 0.65 V (fitc10, formula levels 1.82 / 2.40 V) and 0.85 V (`eh_v08500_m10000`, same parameters as
  `fc10_vth085`; formula levels 1.62 / 2.20 V). Same 20-sample subset, Variant 3 warm start, 2500 µs window, not
  instrumented. 0.85 V uses the nominal warm start, as 3A-T did (approximation).
- **1D:** ΔV₁ ∈ −200…+200 mV in 25 mV steps with V₂ at the formula value; ΔV₂ likewise with V₁ at the formula value.
  V₁ is both the calibration and the C1 level (one host level).
- **Diagonal (run in the 2D phase whatever the 1D result):** ΔV₁ = ΔV₂ = −δ for δ ∈ −200…+200 mV in 25 mV steps. A host
  that believes |V_th| is higher than it is by δ uses exactly these levels. **The |V_th|-knowledge requirement is read
  from the diagonal.**
- **Coarse 2D grid:** 50 mV steps, chosen after the 1D result to cover the region where both 1D sweeps are within
  5 points of nominal, plus one step beyond each edge. Recorded as E5 before it runs.
- **Criterion:** "within 5 points of nominal" = accuracy ≥ (zero-offset accuracy at that |V_th|) − 5 points, on the same
  20 samples. With N = 20 one sample is 5 points, so this means at most one extra wrong sample; the tolerance band is
  the contiguous range of offsets around 0 that meets it. Wilson intervals are given; the band is noisy at N = 20.

## E6. Lower |V_th| edge (B5), declared 2026-10-25 after one diagnostic probe pair, before any sweep
- **Probe (diagnostic, recorded as such):** #81 at |V_th| 0.45 and 0.55 V, fixed levels, every node saved
  (`raw/b5_probe/`). Reading: after `rstb` releases (151 µs) each `na` can fall only through X84 (10/120). The comparator
  output `d` is clamped near `vls` (≈ 2.7–2.9 V) by the 468/15 sense device, so the trip driver X83 (200/10) sees
  V_SG = 3.3 − d ≈ 0.4–0.6 V in its "off" state. At 0.45 V, X83 conducts and holds `na` at ≈ 3.2 V; when `rstr` releases
  (312.5 µs) all five latches regenerate high. At 0.55 V, `na` has only reached 1.68 V by 313 µs (just under the 1.65 V
  trip level).
- **Short runs (#81, to 330 µs):** the latch state at the start of trip counting is input-independent (rows inactive
  until 301 µs, calibration the same for every input). "Stuck" = any `na` > 1.65 V at 320 µs (protocol time). Fine
  sweep |V_th| 0.44–0.66 V in 10 mV, then bisection to 1 mV, per host policy.
- **Host-only policies (no circuit change):** `fixed` (1.82/2.40 V, as 3A); `formula` (re-trimmed to the corner);
  `rstb50` (precharge released at 50 µs instead of 150 µs, so `na` has 100 µs longer to fall: the campaign specification's precharge
  timing); `Vcal-200`, `Vcal-400` (calibration row level 200/400 mV below V₁: more dummy-column current, higher `ref`,
  higher `vls` and `d`, X83 further off); `rext300` (reset phase 300 µs longer).
- **Full runs (20 samples):** |V_th| 0.45–0.55 V in 10 mV for `fixed` and `formula`. For the host policy with the
  lowest threshold: the same grid plus 0.65 V (to check that it costs nothing at nominal). A policy that changes the
  nominal result is reported as a trade-off, not a fix.
- **Circuit fixes** (e.g. a stronger X84, `d` driven to VDD, an `na` reset device): proposals only, not run.

## E8. V_th-learning methods (B3), declared 2026-10-25 after method-development runs on global corners, before the MC
- **Development runs (recorded as such, `scratch/`, not results):** the replica and both host-only methods were tried on
  global corners (|V_th| 0.45–1.0 V, µ ×1/×0.7/×0.5, no mismatch) to fix their parameters. Changes made from them:
  replica 2-point → 3-point extraction (2-point had up to 47 mV error from contact-resistance degeneration); a2 single
  step (V₂ 1.9/2.1 V: up to 38 mV error, no result at 1.0 V/µ ×0.5) → two steps. No classification run was used.
- **(b) rep — replica TFT, Variant 3R (circuit addition, proposal):** one extra TFT, W/L = 300/54 µm (the crossbar L),
  on its own three pads, not connected to the classifier. 135 TFTs. Host: source 3.3 V, drain 0 V via a current meter,
  gate at V_SG = 1.4/1.7/2.0 V; √I = a(V_SG − |V_th| − I·R) solved exactly for (a, |V_th|, R). Mismatch:
  DVTH ~ N(0, anchor·√(780/(300·54))) from its own stream `default_rng([die seed, 1])`, so the classifier's draws are
  unchanged.
- **(a1) host supply-current transfer (host-only, needs a current meter on the host's VDD supply):** after a normal
  300 µs reset start with `rstr` held low (rails clamped by the reset switches, latches held in reset) and `phib` high
  (dummy columns isolated), the rows ramp 3.3 → 1.3 V over 4 ms. ΔI_DD = I_DD − I_DD(rows 3.3 V); the same 3-point
  extraction at the V_SG where ΔI_DD = 5, 20, 45 µA.
- **(a2) race timing (host-only, digital outputs only):** calibration input x = 0, V₁ = 1.82 V, the host times the first
  output edge after C2 starts. Step 1: V₂ = 1.8/2.0 V → estimate 1. Step 2: V₂ = 3.3 − estimate 1 − {0.45, 0.30} V →
  estimate 2. Square law per step: r = √(t_b/t_a), |V_th| = (r·B − A)/(r − 1).
- **Offsets:** each method's raw estimate minus 0.65 on the nominal die (0.65 V, µ ×1, no mismatch) is a design-time
  constant subtracted from every later estimate (per step for a2).
- **Levels:** V₁ = 3.3 − |V̂_th| − 0.83, V₂ = 3.3 − |V̂_th| − 0.25, rounded to 1 mV. Measurement noise and meter
  resolution are not modelled.
- **MC:** anchors 20 and 35 mV, `pelgrom_vth` (µ and R_C nominal), 10 dies per anchor, die seed = 1000·anchor + die
  (dies 1–5 have the 3B-V V_th draws). Global |V_th| per die: stratified uniform over 0.55–0.95 V (one die per 40 mV
  stratum; order and offsets from `default_rng(9000 + anchor)`). µ nominal.
- **Per die:** estimates by rep, a1 and a2, then 20-sample classification with levels from each estimate and from the
  true global |V_th| (`ideal`). A configuration shared by two policies is simulated once.
- **Errors:** V̂ − global |V_th|, and V̂ − (global + W-weighted mean crossbar DVTH).
- **Best method (for B4):** the highest pooled accuracy over both anchors (400 runs). If two are within 2 correct runs,
  the smaller RMS estimate error wins. If the two host-only methods tie with the replica, the host-only one wins (no
  circuit change).

## E7. Aging map (B4), declared 2026-10-25 before running
- Grid: ΔV_th ∈ {0, +0.10, +0.20, +0.30, +0.35} V from 0.65 V × µ ∈ {×1, ×0.85, ×0.7, ×0.6, ×0.5}, global corners
  (`eh_v*_m*`), no mismatch. PROXIES: DNTT family V_th shift +0.1 to +0.35 V under bias stress; mobility halves after
  ≈ 8 months in air. Same 20 samples, nominal warm start (approximation), 2500 µs window.
- Policies: `none` (1.82/2.40 V), `ideal` (formula at the true |V_th|), and the B3 best method (formula at that
  method's estimate on the aged die). All three methods' estimates are computed on all 25 cells (cheap), so the
  estimate-error map is reported for every method; classification runs only for the best one.
- The timing-recovery test for µ-limited cells is declared separately (E9) before it runs, after the map is in.
- **Amendment 2 (2026-10-25, after the first standby set):** at 10⁴ s the power still changed 1.9 % over the last decade
  (100.1 → 98.2 µW), which fails the < 1 % rule above. Standby is rerun to 10⁵ s (the s03 test showed 98.2 µW at both
  10⁴ and 10⁵ s). The single-stage test file `raw/b1_standby/s03.json` was deleted (superseded tooling).
- **Amendment to a1 (2026-10-26 ≈ 21:00 UTC, disclosed post-hoc change; no classification run had used an a1
  estimate yet):** with `phib` held high from t = 0, the a1 transient of die an35_d01 (global |V_th| 0.57 V) stalled at
  its first microseconds (no result after the 7200 s timeout; 30 µs did not finish in 5 min). The same die runs normally
  when the reset phase uses the protocol's sampler setting. New a1 sequence: `phib` low / `phi` high during reset as in
  every classification, switched at 290 µs (sampler off before the ramp at 300 µs); I_DD baseline averaged over
  293–300 µs (after that edge). **Every a1 estimate was recomputed with it** (nominal offset, all B3 dies, all B4 cells,
  `scripts/b3_redo_a1.py`); the superseded values stay in the estimate files as `a1_superseded_phibhigh` and the runs in
  `raw/b3/a1_superseded_phibhigh/`. The stall itself is reported as a tooling anomaly (it is a solver-start problem,
  not a circuit behaviour I can vouch for).
